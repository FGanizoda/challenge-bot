# Задание: Telegram-бот для 60-дневного челленджа по здоровью спины и суставов

Ты — Claude Code. Прочитай этот файл целиком, потом работай по этапам из раздела 10. Пользователь говорит по-русски, все тексты бота и все твои сообщения пользователю — на русском.

## 1. Контекст

Группа друзей (сейчас 4 человека, потом больше) проходит 60-дневный челлендж: у всех проблемы с поясницей, коленями, остеохондроз, и всем сложно с дисциплиной. Каждый день каждый участник выкладывает в Telegram-группу короткое видео (30–60 секунд) своих упражнений. Бот автоматизирует учёт, напоминания и итоги, чтобы никто не вёл таблицу вручную.

Старт: понедельник 2026-11-09 (день 1). Финиш: 2027-01-07 (день 60). Часовой пояс: Asia/Tashkent (UTC+5, без перехода на летнее время).

Бот работает на компьютере пользователя, который включён постоянно. Публичного IP и домена нет, поэтому используй long polling, не webhook.

## 2. Правила челленджа (бот должен им следовать)

- Отчёт: видео в теме (topic) «Отчёты» до 22:00 по местному времени. Подпись по формату `День N/60 - готово. Самочувствие X/10`.
- Статусы дня (коды совпадают с таблицей учёта группы):
  - `д` — выполнено (видео принято);
  - `щ` — щадящий режим (в подписи есть слово «щадящий»), засчитывается как выполненный;
  - `б` — «больничный», у каждого их 3 за весь челлендж, без штрафа;
  - `п` — пропуск без причины, штраф.
- Безопасность важнее серии: при острой боли человек не обязан выкладывать видео, он берёт `/sick`.
- Участники в парах-напарниках. Если у человека нет видео к 22:00, бот отмечает это для напарника.
- Банк: взнос с человека и штраф за каждый `п`. Суммы задаются в настройках, по умолчанию 200000 и 20000 сум, оба значения примерные.
- Новичок входит в начале недели (понедельник) и идёт со своим днём 1. У каждого участника своя дата старта.
- Контрольные замеры (боль 0–10, наклон вперёд в см, фото осанки) на днях 1, 30 и 60.

## 3. Технический стек

- Язык: **C#**, потому что пользователь знает только C#, и ему предстоит читать и менять этот код. Пиши просто и понятно: без сложных паттернов и магии, короткие методы, комментарии на русском там, где логика неочевидна. Платформа: актуальная LTS-версия .NET (8 или новее), консольный проект на Generic Host (`Host.CreateApplicationBuilder`), `async/await`.
- Telegram: NuGet-пакет `Telegram.Bot` (последняя стабильная версия), long polling.
- Расписание: свой `BackgroundService`, который раз в минуту сверяет местное время с расписанием (Quartz не нужен). Время всегда берётся через `TimeProvider`, а не через `DateTime.Now`, чтобы его можно было подменить в тестах и в режиме симуляции.
- SQLite через Entity Framework Core (`Microsoft.EntityFrameworkCore.Sqlite`), один файл `challenge.db`. Для простоты создавай схему через `EnsureCreated()`, миграции не нужны.
- Настройки: `appsettings.json` и типизированный класс настроек (`IOptions<ChallengeOptions>`). Тесты: xUnit. Экспорт в Excel: `ClosedXML`.
- Структура решения: проект `ChallengeBot` (папки `Handlers`, `Jobs`, `Logic`, `Data`, `Texts`, `Config`), проект `ChallengeBot.Tests`, `appsettings.json`, `README.md`.
- Чистую логику (подсчёт дня, статусы, штрафы, банк) выноси в отдельные классы без зависимости от Telegram и базы, чтобы их можно было тестировать.
- Часовой пояс: `TimeZoneInfo` для `Asia/Tashkent`. На Windows проверь, что идентификатор находится (если нет, используй `West Asia Standard Time`), и покрой это тестом.

## 4. Настройки (`appsettings.json`, секция `Challenge`; токен отдельно)

```
BOT_TOKEN=             # пользователь вставит сам, не проси прислать в чат
TZ=Asia/Tashkent
CHALLENGE_START=2026-11-09
CHALLENGE_DAYS=60
DEADLINE=22:00
REMINDER_TIMES=18:00,21:00
MORNING_TIME=08:00
WEEKLY_SUMMARY=SUN 20:00
SICK_LIMIT=3
DEPOSIT=200000
FINE=20000
MIN_VIDEO_SECONDS=10
REQUIRE_VIDEO_NOTE=false   # true = принимать только кружки (видеосообщения), их нельзя загрузить из старых записей
ADMIN_IDS=                 # через запятую; если пусто, админы — админы группы
```

Ключи выше положи в `appsettings.json` с этими значениями по умолчанию (названия приведи к стилю C#, например `SickLimit`). `BOT_TOKEN` в `appsettings.json` не лежит: он читается из переменной окружения `BOT_TOKEN` или из файла `appsettings.Local.json`, который добавлен в `.gitignore`. Токен, `appsettings.Local.json` и `challenge.db` никогда не попадают в git, в логи и в твои ответы.

## 5. Данные (SQLite)

- `participants(user_id PK, username, display_name, start_date, partner_user_id NULL, active, joined_at)`
- `days(user_id, date, status, wellbeing NULL, message_id NULL, created_at, PRIMARY KEY(user_id, date))`, где `status` одно из `done`, `gentle`, `sick`, `miss`
- `settings(key PK, value)` — `chat_id`, `reports_thread_id`
- `events(id, ts, kind, payload)` — журнал для отладки и разбора споров

Видео бот не скачивает и не хранит, только `message_id`. Номер дня участника считается как `(локальная дата − start_date) + 1`, допустимы дни 1–60.

## 6. Поведение бота

**Приём отчёта.** Сообщение засчитывается, если: оно в теме «Отчёты» (`message_thread_id` совпадает с сохранённым), отправитель зарегистрирован, в нём `video` или `video_note` (при `REQUIRE_VIDEO_NOTE=true` только `video_note`), длительность не меньше `MIN_VIDEO_SECONDS`, сообщение не пересланное, день участника в диапазоне 1–60. Дата считается по `message.date` в часовом поясе TZ. Один день засчитывается один раз. Из подписи регулярным выражением достаются `самочувствие N/10` и слово «щадящий». В ответ бот ставит реакцию ✅ на сообщение (если реакции недоступны, отвечает короткой фразой «День N/60 принят»), без длинных текстов.

**Напоминания (по расписанию, в тему «Отчёты» или общий чат).**
- 08:00: «День N/60», у кого какой этап (1–14, 15–40, 41–60).
- 18:00 и 21:00: кто ещё не отчитался сегодня (с упоминанием), и сколько осталось до 22:00.
- 22:00 (дедлайн): всем без записи за день ставится `miss`, в группе короткое сообщение, у кого пропуск, и упоминание напарников этих людей. Если у человека `/sick` на сегодня или он уже отчитался, ничего не происходит.
- Воскресенье 20:00: итоги недели (кто сколько дней, у кого остались «больничные», остаток банка) и вопрос про самочувствие и препятствия.
- Дни 1, 30, 60 участника: напоминание про контрольные замеры.

**Команды.**
- `/join` — зарегистрироваться; если сегодня не понедельник, бот ставит старт на ближайший понедельник и пишет об этом.
- `/status` — мой прогресс: день, дни `д`/`щ`/`б`/`п`, «больничные» осталось, штрафы.
- `/table` — компактная таблица группы за последние 7 дней и общий итог.
- `/bank` — взносы, штрафы, остаток.
- `/sick` — «больничный» на сегодня, уменьшает остаток; при нуле бот объясняет, что лимит исчерпан, и предлагает обсудить с группой, ничего не штрафует автоматически.
- `/pair @a @b`, `/mark @user YYYY-MM-DD д|щ|б|п`, `/setstart @user YYYY-MM-DD`, `/export` — только для админов. `/export` присылает xlsx с листами: учёт по дням, итоги, список участников.
- `/setup` — только админ группы, вызывается в теме «Отчёты»: сохраняет `chat_id` и `reports_thread_id`.
- `/help` — список команд и правил кратко.

**Пары.** Автоматически ротируются каждые 2 недели (при нечётном числе одна тройка), админ может назначить вручную через `/pair`.

**Забота о здоровье (важно).** Если в подписи самочувствие 4/10 или ниже, бот мягко предлагает щадящий режим на сегодня. Если 3 дня подряд 4/10 или ниже, предлагает показаться врачу. Бот не даёт советов по упражнениям, диагнозам и нагрузке и не стыдит за пропуски: тон нейтральный и поддерживающий.

## 7. Первичная настройка (опиши в README по шагам, простым языком)

1. Создать бота у @BotFather командой `/newbot`, взять токен и положить в `appsettings.Local.json` (или в переменную окружения `BOT_TOKEN`).
2. У @BotFather выполнить `/setprivacy` → Disable (иначе бот в группе увидит только команды и не увидит видео), затем добавить бота в группу как администратора.
3. В группе должен быть включён режим тем, и в ней создана тема «Отчёты».
4. В теме «Отчёты» админ выполняет `/setup`, участники — `/join`.
5. Сначала проверить на тестовой группе из 1–2 человек, потом переносить в боевую.

Токен пользователь вставляет сам. Не проси его присылать токен в чат и не печатай его в логах.

## 8. Запуск на компьютере пользователя

Операционную систему не знаешь, поэтому определи её сам (или спроси). Собери релиз командой `dotnet publish -c Release` и настрой запуск как сервис с автозапуском и перезапуском при падении. Для Windows используй `AddWindowsService()` и регистрацию службы через `sc.exe`, для Linux `AddSystemd()` и unit-файл systemd, для macOS launchd. Опиши, как отключить спящий режим компьютера. Логи пиши в файл с ротацией. Раз в сутки делай копию `challenge.db` в папку `backups/` и храни последние 14. При старте бот должен переживать перезагрузку: расписание строится заново, ничего критичного не хранится только в памяти, а пропущенный за время простоя дедлайн дозакрывается при запуске, если это ещё допустимо по дате.

## 9. Тесты и критерии приёмки

Обязательные unit-тесты (xUnit) на чистую логику: номер дня, границы 1 и 60, дату из `message.date` около полуночи, повторный отчёт в тот же день, лимит `/sick`, расчёт штрафов и банка, вход новичка в среду, ротацию пар.

Режим проверки: `dotnet run -- --simulate` с подменённым `TimeProvider`, чтобы прогнать весь день, неделю и дедлайн без ожидания.

Готово, когда:
- на тестовой группе видео засчитывается, реакция ставится, повтор не задваивает день;
- в 22:00 пропуск фиксируется и напарник упомянут;
- `/sick`, `/status`, `/table`, `/bank`, `/export` работают;
- после перезапуска бота данные и расписание на месте;
- в репозитории нет токена и базы, а README позволяет настроить бота без помощи разработчика.
